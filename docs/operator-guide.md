# Aegis Operator Guide

This guide covers installation, configuration, and runtime operation of Aegis. It assumes a private research deployment.

For release-review demos, use [`docs/demo-guide.md`](demo-guide.md).

---

## §1. Install & first-run

### Prerequisites

- **Bun ≥ 1.1** on PATH. Install: <https://bun.sh>.
- **Python ≥ 3.11** on PATH. Required by `aegis-mcp`.
- An LLM API key — at minimum `ANTHROPIC_API_KEY` for Anthropic. See §4 for other providers.

### One-command install

From the repo root:

```bash
bash aegis/scripts/install.sh
```

The script:
1. Verifies Bun + Python.
2. Creates the `aegis-mcp` Python venv at `aegis-mcp/.venv`.
3. Installs `presidio-analyzer`, `presidio-anonymizer`, `spacy`, and the `en_core_web_sm` model.
4. Generates `.mcp.json` at the repo root via `aegis/scripts/generate-mcp-config.sh`.
5. Runs `bun install` and `bun run build` for the TS half.
6. Smoke-tests with `bun run test:unit`.

Re-running the script is safe — every step is idempotent.

### First REPL session

```bash
cd aegis && bun run build && ./dist/aegis --phi-mode research
aegis> /patient load tests/fixtures/synthea_minimal.json
aegis> /template set soap
aegis> Draft a SOAP note for this patient.
aegis> /note export ./notes/visit.md
```

Expected: SOAP-fenced sections appear in `./notes/visit.md`; `/audit show` shows a session log.

## §2. `.mcp.json` and the Python venv

### What `.mcp.json` does

Aegis launches the Python MCP server (`aegis-mcp`) as a stdio subprocess on REPL boot. The server hosts FHIR parsing, Presidio de-id, Jinja template rendering, and the clinical validator. The launch command lives in `.mcp.json` at the repo root — a per-machine, gitignored file generated by `aegis/scripts/generate-mcp-config.sh`.

The template at `.mcp.json.template` shows the expected shape; the generator substitutes the absolute path to the venv's `aegis-mcp` entry-point.

### Regenerating after a venv move

If the venv path changes (machine move, venv rebuild):

```bash
bash aegis/scripts/generate-mcp-config.sh
```

The script overwrites `.mcp.json` in place. The TS side picks up the new path on next REPL launch.

### Venv layout

```
aegis-mcp/
├── .venv/                         # python3.11 -m venv .venv
│   └── bin/aegis-mcp              # stdio entry point referenced from .mcp.json
├── pyproject.toml                 # build-backend = local; deps pinned
└── src/aegis_mcp/                 # server + tools + templates + validator
```

The venv is per-machine and not version-controlled. Recreate via:

```bash
cd aegis-mcp
python3.11 -m venv .venv
.venv/bin/pip install -e '.[dev]'
.venv/bin/python -m spacy download en_core_web_sm
```

## §3. Audit log schema

Audit logs live at `~/.aegis/audit/<sessionId>.jsonl`. One file per session, append-only, fsync'd on every entry, mode `0600`. The log is the canonical record of every LLM round-trip and every export.

### Entry shape (common fields)

Every entry has:

```json
{
  "ts": "2026-05-07T14:22:01.123Z",
  "type": "<event type>",
  "requestId": "<per-request id, or 'export-gate' for export events>",
  "mode": "strict|research|off",
  ...event-specific fields
}
```

### LLM round-trip events

Common to both rows below: every `llm_request` / `llm_response` carries `provider`. Source of truth: [`auditMiddleware.ts`](../aegis/src/medical/middleware/auditMiddleware.ts).

| `type` | When | Strict-mode payload | Research-mode payload |
|---|---|---|---|
| `llm_request` | Before each outbound LLM call | `model` (effective wire model), `deidVersion`, `redactedPayloadHash` (sha256 hex over the redacted request), `phiEntityCounts`, `phiHashes` (sha256 of each PHI entity from `ctx.phiMapping`) | `model`, `fullRequest` (the plaintext snapshot stashed by `phi.outbound` before placeholders were substituted) — **no** `phiEntityCounts` or hashes |
| `llm_response` | After each inbound LLM response | `usage` (input/output tokens), `warningCount` (length of `clinicalValidator`'s decorated `warnings`) | `usage`, `warningCount`, `fullResponse` (post-`phi.inbound` restored content) |

**Off mode writes no LLM round-trip rows.** [`middlewareWiring.ts:61`](../aegis/src/medical/runtime/middlewareWiring.ts) returns empty inbound + outbound chains when `phiMode === 'off'`, so neither `audit.outbound` nor `audit.inbound` ever runs. The audit log can still grow during an off-mode session — `/note export` produces export events through `NoteExportGate` regardless of mode — but `llm_request` and `llm_response` entries are strict/research only.

Validator output is **not** a separate audit event. The clinical validator pushes its `ValidatorWarning[]` into `AppState.validatorWarnings` (REPL banner) and decorates the inbound response with `warnings: [...]`, which `audit.inbound` reads to compute `warningCount` on the same `llm_response` line. To inspect the warnings themselves, read `AppState` or the in-memory note — they don't survive into the audit log by design.

### Export events

Every `/note export` produces an *intent → completed* (or *intent → failed*) pair, plus optional decline events:

| `type` | When | Notable fields |
|---|---|---|
| `note_export_intent` | Pre-write, post-attestation | `target`, `bytes`, `phiEntityCounts`, `attestation: true`, `attestation_kind: 'clinical'\|'research_use'`, `finalRedactedHash` |
| `note_export_completed` | After successful disk write | `target`, `bytesWritten`, `finalRedactedHash`, `attestation_kind` |
| `note_export_declined` | Clinician answered N at sign-off (or PHI extra-confirm) | `target`, `phiEntityCounts`, `attestation_kind`, optional `reason` |
| `note_export_failed` | Write failed (target exists, IO error, post-write audit failure) | `target`, `error`, `reason` |
| `note_export_validator_error` | Validator threw during pre-export check | `target`, `error` |
| `note_export_tmp_cleanup_failed` | Atomic link succeeded but tmp-file cleanup failed | `target`, `tmpPath`, `error` |

### `attestation_kind` semantics

- `'clinical'` → strict-mode export; clinician attested to clinical accuracy.
- `'research_use'` → research/off-mode export; user acknowledged the output is a research/operational draft, not a medical record.

The kind is stamped on intent, completed, and declined events. It is *not* stamped on `note_export_failed`/`_validator_error`/`_tmp_cleanup_failed` — those carry no attestation context.

### Strict-mode invariants

- Every `llm_request` MUST have `redactedPayloadHash` and MUST NOT have a `fullRequest` field.
- The audit log file mode MUST be `0600` (verified at every `append`).
- Lines that fail `JSON.parse` are rendered as `<corrupt line>` by `/audit show` but never silently dropped from disk.

Source of truth: [`aegis/src/medical/audit/AuditLogger.ts`](../aegis/src/medical/audit/AuditLogger.ts) and [`aegis/src/medical/audit/redaction.ts`](../aegis/src/medical/audit/redaction.ts).

## §4. Provider matrix, trust model, `.aegisrc`

### Provider matrix

Aegis ships five session-provider presets:

| `id` | Adapter | Default model | Capability flags |
|---|---|---|---|
| `anthropic` | Anthropic native | `claude-haiku-4-5-20251001` | streaming, toolUse, promptCache |
| `openai` | OpenAI-compatible (with `https://api.openai.com/v1`) | `gpt-4o-mini` | streaming, toolUse |
| `glm` | GLM native | `glm-4-plus` | streaming, toolUse |
| `minimax` | Minimax native | `abab6.5-chat` | streaming |
| `openai-compatible` | OpenAI-compatible (any base URL) | `auto` (configure via `.aegisrc`) | configurable |

Switch at runtime: `/provider set <id>`. Lookup credentials: `/provider creds <id>` (interactive paste; OS keychain). Show active: `/provider list`.

### Trust model

Aegis treats `phiMode` as the load-bearing safety axis:

- **`strict`** — the only mode for real PHI. PHI is redacted before every outbound call (Presidio rule-based). `redactedPayloadHash` only in audit; never `fullRequest`. Export gate runs the clinician-attestation flow; `--full` exports require an extra PHI-to-disk confirmation.
- **`research`** — synthetic / de-identified data only. PHI middleware still runs (defense in depth), but audit logs may include the full request. Export gate uses the research-use acknowledgment.
- **`off`** — no medical data; all medical middleware is short-circuited. Export gate uses the research-use acknowledgment. The `off` mode CANNOT be set at runtime via `/phi-mode` — it can only be selected at process launch via `--phi-mode off`.

The user is responsible for selecting a mode appropriate to the data. Aegis cannot verify a bundle is or is not real PHI.

### `.aegisrc`

Aegis loads `.aegisrc` from `$PWD/.aegisrc`, falling back to `~/.aegisrc`. JSON shape (validated by zod at load — invalid files silently fall back to defaults rather than crashing):

```json
{
  "allowlist": ["anthropic", "openai-compatible"],
  "providers": {
    "openai-compatible": {
      "baseURL": "https://api.together.xyz/v1",
      "modelId": "meta-llama/Llama-3.1-70B-Instruct-Turbo",
      "knownModels": [
        "meta-llama/Llama-3.1-70B-Instruct-Turbo",
        "meta-llama/Llama-3.1-405B-Instruct-Turbo"
      ]
    }
  }
}
```

**`allowlist`** — if non-empty, restricts which provider ids are usable in the current session. Strict mode + an `allowlist` is the recommended setup for a BAA-equipped deployment: list only providers with a valid data-handling agreement.

**`providers.<id>`** — per-provider config:
- `baseURL` (optional, string, must be a valid URL): for `openai-compatible` this is the only way to point at a non-OpenAI endpoint.
- `modelId` (optional, string): default model for that provider; used when `/provider set <id>` runs without an explicit model selection.
- `knownModels` (optional, string[]): models surfaced in the two-level `/model` picker.

Source of truth: [`aegis/src/medical/config/aegisrc.ts`](../aegis/src/medical/config/aegisrc.ts).
